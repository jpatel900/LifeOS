# ADR-0008: Widen agent trust rungs for current-generation models

**Date:** 2026-08-04 | **Status:** Accepted — owner ratified all four moves 2026-08-04, item by item, with one edit: move 2's window is **30 minutes** (owner-set; the proposal drafted 24 hours). Moves take effect as their enabling changes land (see Consequences).

**Context:** The repo's automation tiers and self-approval rules were calibrated in May-July 2026 against earlier-generation models. Since then the guard surface has grown substantially: risk classifier, path allowlists with shrink-only policies, doc-registry and coherence guards, public-evidence hygiene, migration drift detection, provider canary, Main Red Guard auto-revert, and the safe-automerge demotion path — all CI-enforced. INV-10 (autonomy graduation gate) defines the checklist any expansion must clear. Meanwhile every trust expansion is spending owner attention on merges the guards already police.

**Decision (proposed rung moves, each independently ratifiable):**

1. **Widen T0 to guard-policed mechanical classes.** Add to the safe-automerge allowlist: `docs/program/**` (program-state updates — the freshness this repo keeps losing) and test-only PRs that strictly ADD assertions (no deletions/weakenings — the risk classifier already detects assertion changes). Gate: INV-10 checklist filled per class, including pre-registered decision-data criteria (the item the docs-only lane skipped).
2. **Agent-merge of own low-risk green PRs with a review window.** Replace the blanket self-approval block for `risk:low` non-T2+ PRs with: auto-merge arms only after a **30-minute** open window with the owner notified (owner-set at ratification; the draft proposed 24h — at 30 minutes this works as notify-then-merge, and the owner's veto is in practice a revert rather than a pre-merge stop, accepted knowingly given the low-risk-only scope), and the Main Red Guard demotion applies to this class automatically on any red-main incident it causes. Owner can revert to blanket-block by removing one allowlist entry.
3. **Standing authorization for repo-state reconciliation.** Doc fixes that make a doc match verified repo reality (the class this cleanup program is) get a standing owner-ratified umbrella issue, so each instance needs a PR but not a fresh ratification.
4. **Session-length gates replace per-step gates.** For work inside an owner-ratified program (e.g. the Final UX Loop), agents proceed through multi-slice sessions without per-slice check-ins; the gates are the program's own re-score/pin rules plus the OWNER-GATE marker rubric. This codifies what already works in practice.

**Explicit non-moves (binding regardless of model capability):** external calendar writes, any outbound communication, RLS/migrations/schema changes, secrets and production env, data deletion, and spending money all stay human-gated. No irreversible/external class ever auto-executes (ADR 0002 D1's "never" rung is untouched).

**Rationale:** Trust should attach to the guard surface, not the model vintage. Every proposed move is (a) reversible by one allowlist edit, (b) auto-demoting on incident via the existing Main Red Guard path, and (c) INV-10-gated. The cost of NOT moving is real: owner-merge queues delay the program the owner declared terminal, and stale-by-waiting docs regress the truth-store this week's cleanup established.

**Alternatives rejected:** Blanket "trust the model more" without per-class gates — rejected; INV-10 exists precisely to prevent vibes-based graduation. Keeping everything owner-merged — rejected as the status quo this ADR examines; it spends the scarcest resource (owner attention) on the classes guards already police. Model-conditional rules ("if the model is X, allow Y") — rejected; capability-neutral per-class gates age better (see `docs/agent/MODEL_LANES.md`).

**Consequences (ratification record, 2026-08-04):** Move 1a (docs/program/** auto-merge) is effective immediately — `docs/**`was already on the safe-automerge path allowlist, so the enabling change is authorization: agents may apply the T0 labels to program-state PRs (noted in`.github/AGENT_AUTOMATION_POLICY.md`). Move 1b (strictly-additive test PRs) and move 2 (30-minute self-merge window) each need machinery — an enabling issue tracks each, and each enabling PR files the full INV-10 checklist and changes policy + workflow in the same owner-merged PR (T2). Move 3 is effective via its standing umbrella issue. Move 4 is effective by this ADR alone. Decision data (merge outcomes, incidents) is collected from each class's first day so graduation and demotion stay evidence-based.

**Amendment (owner, 2026-08-05):** move 2's window is reduced from 30 minutes to INSTANT: the notification moves to Telegram (1-2 lines at PR open) and auto-merge arms immediately, making the CI check runtime the effective veto window (~4-20 min by PR type). The owner chose NO delivery fallback, knowingly: a failed or unconfigured Telegram send does not delay the merge. This also creates the policy's single notify-only external-channel carve-out. Everything else in move 2 stands (scope, blocking labels, red-main pause, demotion).

**Reversal trigger:** Any red-main incident or hollow-green event attributable to a widened class demotes that class automatically (existing demotion tooling); two incidents in 30 days for the same class revert the class's rung permanently pending a fresh INV-10 run.

**Amendment (owner, 2026-08-30):** Move 2 (and the safe-automerge lane from move 1) never applies to a PR that carries an unchecked OWNER-GATE task-list line (any GFM bullet, blockquoted or not), states "OWNER RATIFICATION REQUIRED" anywhere in its body, has an "OWNER-GATE" heading in its body, or carries the `owner-gate` label — checked before every other route-specific rule in each lane, and failing closed (never arming) if the PR body can't be read. Draft was already a separate pre-existing rule in each lane before this amendment and stays one; it is not part of this shared check, but has the same effective priority (nothing bypasses it either). This closes a real gap: on 2026-08-30 the safe-automerge sync armed auto-merge on a ratification PR (#935, which said "OWNER RATIFICATION REQUIRED" in its body) because neither lane had ever checked PR body or title content, only labels and changed paths. The check lives once, in `scripts/agent/automation-policy.mjs` (`evaluateOwnerGateBlock`), and `check-safe-automerge.mjs`, `selfmerge-window.mjs`, and Main Red Guard's human-confirmed revert-PR arm (`red-guard-diagnose.mjs`'s `evaluateConfirmArm`) all call it; every one of those three arming paths also disarms an already-armed PR the moment it stops passing, and `safe-automerge.yml`'s disarm step now runs even when the eligibility check itself throws (`if: always()`), so a PR can't stay armed just because the evaluator failed.
